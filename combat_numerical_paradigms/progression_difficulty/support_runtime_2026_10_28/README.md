# 学者、剑士正式接入

2026-10-28。本轮新增学者智能恢复技能次数、剑士完整技能递归，以及每段技能独立播放、伤害、回血和退出取消。连同水手、行商、军人、忍者，目前正式接入6/23项。

## 学者

学者每次攻击（包括保底普攻、被闪避的技能）按概率恢复另一名队友的有限技能使用次数。目标必须已消耗次数，排除自己、无限次技能、未使用技能和已超过最后可用回合的技能。

智能选择按以下优先级，组内按调用方给出的阵容顺位：

1. 当前条件满足且次数耗尽。
2. 当前条件满足、已用过但未耗尽。
3. 当前条件暂不满足且次数耗尽。
4. 当前条件暂不满足、已用过但未耗尽。

“当前条件”包括回合与双方战力比例；次数耗尽判断计入装备额外次数。恢复只减少`uses`，保留历史`casts`与失败概率递增计数，不触发队友立即攻击。实际可用技能仍按下一次正常行动的阵容顺位判定。

这是把用户要求的“智能选择”落成可复现策略；旧研究代码原来随机挑选目标，其旧胜率不冒充本次智能策略的收益。

## 剑士

剑士技能发动后可触发另一名符合条件的剑士完整技能；即使本次攻击被闪避仍可尝试接力。候选必须有技能、满足当时双方战力/回合条件并有剩余次数；排除本次出手者，允许以后递归到先前仍有剩余次数的剑士。

追加成功后不再受接收者原发动率阻挡，但仍消耗其实际技能次数、累计其施法次数，并完整执行暴击、穿透、恢复、流失、削弱、装备等既有管线。上一段伤害/恢复改变的战力条件在选择下一段时重新读取。

同一组最多追加3次，即原始技能1次+追加3次=总计4次。额外技能不插入新的回合、不额外结算回合流失/恢复；对方行动等整组结束。先手标记沿用该组行动，四维与当前战力每次出手重新采样。

设`q=n/(n+k)`，递归深度`d=0`表示原始技能结束后尝试第一次追加：

`p(d) = min(1, swordChance × q(剑士数) × gain) × swordDecay^d`。

先把首次概率封顶，再递减，避免高强度配置让数层概率都被截成100%。`swordDecay`必须在`[0,1)`，`swordExtras`允许0～3。

数值核心每次`Next()`返回一个完整技能及`hasContinuation`。正式播放器一次手动推进会自动连续播放整组，每段都有自己的前移/停留/后退、特效、伤害和回血时点。每段完成延迟回调后才推进下一段，避免上一段回调指向已被替换的战报。

## 调用与候选参数

```csharp
var session = BattleSceneFlow.Enter(new BattleSceneRequest
{
    stage = stage,
    left = playerMembers,
    right = enemyMembers,
    leftSupportBonds = new CombatSupportRules { scholar = true, sword = true },
    autoPlay = true
});
```

`rightSupportBonds`独立配置敌方。默认两个开关均关闭，可与上一轮的`left/rightOpeningBonds`、`left/rightEvasionBonds`和旅行上限一起使用。

| 字段 | 候选 | 含义 |
|---|---:|---|
| countK | 4 | 人数曲线平滑参数 |
| gain | 1 | 强度倍率 |
| scholarChance | 0.30 | 学者概率基系数；实际为`min(1, scholarChance×q(学者数)×gain)` |
| scholarRestore | 1 | 单次最多恢复次数，不超过目标实际已消耗量 |
| swordChance | 0.50 | 剑士首次追加概率基系数 |
| swordDecay | 0.50 | 每层递减倍率 |
| swordExtras | 3 | 最多追加次数 |

参数沿用既有候选，智能目标和概率封顶顺序是明确记录的本轮实现细化；本轮验证机制一致性，没有重新估计最优排阵下的泛用增益。

## 战报、退出与装备边界

- `BattleTurnReport.chainDepth`：0原始技能，1～3追加技能；`hasContinuation`表示仍有待播放的追加。
- `scholarTarget`：获恢复队友的0起始位置，未恢复时为−1；`scholarRestored`为实际恢复次数。
- `BattleSceneResult.leftSupportBonds/rightSupportBonds`：学者判定/恢复次数、剑士触发/实际追加数、最长追加深度等独立摘要。
- 追加已触发但尚未执行时离开，后续播放被取消，不消耗该接收者次数，不计作已执行追加。下一场清空待追加状态。
- 净化装备仍在回合结束生效；现在记录每次命中技能各自的净化额度，前面的剑士不会因后面换人出手而丢失装备触发。
- 原人物、场景、特效时点和位置配置未修改。只跳过对未激活角色槽启动受击协程，防止低人数阶段给隐藏槽发动作。

## 验证与复现

`generate_parity.py`沿用真实`joint_core/bond_core`，在新适配层实现智能目标、逐次净化、递减封顶和每次技能重置治疗通道。旧研究把吸血的标记留到后续追加治疗，会让“当前战力自愈”误用上限；新对照逐次清理该标记，生产核心本身按每次技能正确取基数。旧研究文件与旧结果保持冻结。

- `support_parity.json`：1920场六阶段/四组新机制组合，核对36,342次出手的主人、回合、递归深度、继续标记、恢复目标与次数、闪避/暴击、随机数消耗、链中即时战力和完整终局数据。
- `support_invariants.json`：40项定向检查，含智能优先级、装备额外次数、普攻/未命中恢复、递归边界、条件、次数、完整恢复/流失/装备、概率递减、净化、致死停止和输入隔离。
- `unity_validation.json`：153项新真实场景检查，六阶段完整四技能自动播放、每段独立回血、敌人不插队、恢复后重新出手、回调中离开取消、跨场清零。
- 军人/忍者2400场、开局1920场、旅行2400场、旧核心480场及54+11项机制不变量继续回归。
- Unity另回归军忍142项、人物开局71项、旅行135项、原场景73项及3698项标签检查。
- `baseline_regression.log`为37,500场原基准；最终胜率极差与资产哈希审计见`delivery_checks.json`。

复测入口：`run_numeric_checks.ps1`、`run_unity_checks.ps1`、`verify_delivery.py`。生产源码快照与本轮签名在`delivered_sources/`、`delivery_manifest.json`，旧版本签名不覆盖。
