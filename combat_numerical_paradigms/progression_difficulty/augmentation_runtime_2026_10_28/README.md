# 工程师、贤者、盗贼、杀手正式接入

2026-10-28。沿用已测候选，四项均需调用方显式开启。连同前11项为15/23项；强度系数是可调研究候选，验证重点是生产实现与研究物理一致。

| 身份 | 当前候选与触发口径 |
|---|---|
| 工程师 | 装备四维基数包含显式stats及owner_stats实际贡献；开局增加基数×0.25qg。每次工程师技能发动排队增加基数×0.035qg，回合结束提交，下回合有效 |
| 贤者 | 原生虚弱、四维削弱、最大/已损/固定流失的幅度乘(1+0.25q己g)×max(0,1−0.25q敌g)；原时长与伤害底数保留 |
| 盗贼 | 每次攻击后偷取对方有效各维×min(1,0.015qg)，不超过对方原始剩余各维；双方场内原始属性等量转移，不改角色和装备档案 |
| 杀手 | 技能命中后给敌方下一次技能施加min(1,0.60qg)减疗；重复标记取大值。实际技能选定时消费，包括随后未命中或没有恢复的技能，普攻不消费 |

q=n/(n+4)，g为gain。工程师不放大装备战力或装备技能机制，开局提交先于水手、行商。盗贼攻击不要求命中，旅行上限和临时削弱继续作用于有效属性。

减疗只作用于该技能的恢复请求，在封顶和溢出护盾前计算；回合宏恢复、装备免死独立。当前战力自愈按当次实际当前战力计算被阻止的恢复量。战报增加engineerQueued、stolenStats、killerMarked、appliedHealPenalty、healingPrevented。结果中的减疗累计归于受到减疗的一方。

接入为BattleSceneRequest.leftAugmentationBonds/rightAugmentationBonds，类型CombatAugmentationRules，独立布尔engineer/sage/thief/killer；全部默认关闭。规则、阵容、结果数组均隔离复制，调用方仍决定奖励和退出去向。

验证入口run_numeric_checks.ps1、run_unity_checks.ps1、verify_delivery.py。2880场六阶段六种单项与组合配置逐次对照，同时复核前11项；冻结研究源只经内存适配，未修改旧脚本或旧证据。实际次数、误差、Unity检查、37,500场回归及保护资产哈希见delivery_checks.json。
