# 混合身份交互覆盖补测

2026-10-28。接在23项机制完整验收之后，不修改生产规则或系数，检查混合配置中的真实触发。

原全开启混合配置的女仆长在第3位，六阶段主要由前置冒险者、农民和女仆实际出手，工程师、学者、剑士等后排没有发动。原单项、定向和场景检查仍有效；配置全部开启不能替代交互覆盖。

新增3120场，每阶段520场。阶段内分别等间隔抽取20个已有技能/装备输入，每个做25次身份轮换及一次军人达到人数上限半数的组合。轮换配置把女仆放在所有其他身份后；技能、四维、装备、技能门槛、发动率和次数均不修改。身份赋值是测试输入，不代表真实人物分布。

结果40,479次出手与原生研究管线一致，最大相对误差1.0547118733939e-13。除逐次战报、随机数、使用次数、血量、有效四维及复合事件外，额外逐场对照双方闪避、学者/剑士、五组增益、工程师/贤者/盗贼/杀手、五组战术的状态摘要。

[覆盖表](COVERAGE.md)区分每阶段实际发生的11类动作事件；[联合触发与实际用途](coactivation_cases.json)继续记录同场共现，以及有装备基数的成长、金币实际减伤、减疗实际阻止恢复、复起、果实收获和目标后施法。表格只验证覆盖，不比较构筑胜率；设计胜率继续引用既有最优顺位研究。

本批5人阶段全部技能不限次，因此学者不存在合格恢复目标；10～30人阶段均实际恢复过次数。这个结果保留为真实配表前提，没有为了让计数变正而添加有限次技能。可执行投放条件见[技能供给指导](SKILL_SUPPLY_GUIDANCE.md)。

当前累计25,200场数值对照；此前238项规则检查、1069项场景/生命周期检查、3698项人物标签检查及37,500场原基准回归见上一组冻结验收。本补测没有改变Unity源代码，因而核对生产签名和保护资产，沿用其已完成的场景验证。

复测run_checks.ps1后运行verify_delivery.py；新脚本、来源哈希、覆盖、检查及签名保存在本目录。生产与旧研究快照全部保留。
