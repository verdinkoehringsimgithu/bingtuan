# 五组增益机制正式接入

2026-10-28。新增学生/老师、拜火教、格斗家、侠女、淑女。连同此前六项，当前正式运行时支持11/23项，均需调用方显式开启；其余机制继续按既有设计移植。

## 本轮候选规则

统一人数曲线`q(n)=n/(n+4)`，`gain=1`是当前研究候选强度，调用方可调。不是要求所有地区或阶段强制使用统一强度。

| 身份 | 已实现范围与候选数值 |
|---|---|
| 学生/老师 | 老师技能基础攻击乘`1+0.0015×学生等级总和×gain`；给调用方返回学生经验倍率`1+0.12×老师数×gain` |
| 拜火教 | 教徒技能基础攻击乘`1+0.035×比该技能低阶的教徒数×gain`，阶差按实际技能tier判断 |
| 格斗家 | 全队输出因子乘`1+0.025×q(格斗家数)×gain×(当前回合−1)` |
| 侠女 | 每位侠女首次发动技能后增加一层；后续侠女技能基础攻击乘`1+层数×0.035×q(侠女数)×gain` |
| 淑女 | 覆盖前`min(实际人数,ceil(淑女数/3))`个位置的技能；基础攻击乘`1+0.25×q(淑女数)×gain` |

上述基础攻击因子按老师→拜火教→侠女→淑女顺序接在既有装备因子后。原生恢复技能仍有基础攻击，只增强攻击部分，不放大恢复量。淑女本轮沿用研究中的技能增伤候选，保底普攻不增加该技能因子。

侠女首次以技能发动计，不要求命中；同一位重复施放不能继续叠首次层。其首次本身使用旧层数，结束后才给后续施放增加层。后续重复施放也可受已有全队侠女层强化。

格斗家在回合开始、最大流失结算前更新，原回合内追加技能不额外长回合层。既有读取源队输出的流失也受到当前格斗家因子影响；不额外把该因子塞进原来不读取输出的其他百分比结算。

## 接入

```csharp
var session = BattleSceneFlow.Enter(new BattleSceneRequest
{
    stage = stage,
    left = playerMembers,
    right = enemyMembers,
    leftAmplificationBonds = new CombatAmplificationRules
    {
        academy = true, cult = true, fighter = true, heroine = true, lady = true
    },
    autoPlay = true
});
```

敌方使用`rightAmplificationBonds`，可与开局、闪避、学者剑士和旅行规则同时传入。规则与真实阵容等级在进入时复制，不改玩家顺位。

`CombatMember.level`由`BattleMember.level`传入，正式角色仍为1～30级。纯数值历史测试缺少level字段时默认30，新的等级机制对照会显式提供1～30级；不从四维预算反推等级。阶级标注、数值品阶与培养等级保持不同概念。

战报`bondDirectMultiplier`记录本轮四项技能直伤因子，`bondOutputMultiplier`记录格斗家因子，`heroineFirst`标记本次新增首次层。结果`left/rightAmplificationBonds`含人数、学生等级总和、淑女覆盖位置、侠女层和经验倍率。

经验倍率只给调用方用于**学生**的经验结算。基准经验、奖励条件、存档发放仍由已有业务决定；本模块不创建经验值或自动发奖。中断结果同样可能有摘要，不应把摘要存在当作已经发奖。

## 验证

- `amplification_parity.json`：3360场六阶段/七种单项及组合配置、58,552次出手，与原生研究动作管线对照；同时覆盖此前六项机制。核对逐次归因因子、首次层、回合、主人、递归、恢复、RNG及完整战斗终局。
- `amplification_invariants.json`：29项规则边界，含真实等级、老师不放大治疗、阶差、格斗家新回合流失、侠女每人首次、淑女位置、重复输入隔离和非法参数。
- `unity_validation.json`：132项真实场景检查，六阶段等级快照、老师/淑女组合、逐回合成长、首次/重复侠女、拜火教阶差和结果副本。
- 旧9120场数值对照、40+54+11项机制检查，以及学者剑士153、军忍142、开局71、旅行135、原场景73及3698项标签检查继续回归。
- `baseline_regression.log`保存37,500场原基准，结果和保护资产哈希见`delivery_checks.json`。

新对照沿用已经验证的学者/剑士适配层，再启用冻结研究中的五项既有效果，未修改旧研究或冒充新的最优顺位收益研究。固定机制输入中的身份/等级用于一致性测试，不能当作真实玩家收集分布。

复测入口为`run_numeric_checks.ps1`、`run_unity_checks.ps1`、`verify_delivery.py`。最终生产快照和签名在`delivered_sources/`、`delivery_manifest.json`；旧版本保持冻结。
